# Deployment Guide

This document explains how to deploy the Beyond Clarity website to GitHub Pages.

## Overview

This site uses **11ty (Eleventy)** as a static site generator with server-side rendering. The deployment strategy follows best practices:

- **Source code** (in `site/`, `.eleventy.js`, etc.) stays in the `main` branch
- **Generated site** (in `_site/`) is automatically deployed to GitHub Pages
- **No manual file copying** - everything is automated via GitHub Actions

## Architecture

```
│  - site/        │

         │

         ▼

│  GitHub Pages    │  (gh-pages branch or Pages)

└─────────────────┘
```

## Automated Deployment (Recommended)

### Setup

1. **Enable GitHub Pages** in your repository settings:
   - Go to Settings → Pages
   - Source: "GitHub Actions" (not "Deploy from a branch")
   - Save

2. **Push to main branch** - that's it! The workflow will:
   - Build the site (`npm run build`)
   - Deploy `_site/` to GitHub Pages
   - Happens automatically on every push to `main`

### Workflow File

The deployment is handled by `.github/workflows/deploy.yml`, which:
- Triggers on pushes to `main` branch
- Installs Node.js and dependencies
- Builds the site using 11ty
- Deploys the `_site/` directory to GitHub Pages

### Manual Trigger

You can also manually trigger deployment:
- Go to Actions tab in GitHub
- Select "Deploy to GitHub Pages" workflow
- Click "Run workflow"

## Local Development

1. **Install dependencies:**
   ```bash
   npm install
   ```

2. **Build locally:**
   ```bash
   npm run build
   ```

3. **Preview locally:**
   ```bash
   npm run serve
   # or
   npx @11ty/eleventy --serve
   ```

4. **View generated site:**
   - Open `_site/index.html` in a browser
   - Or use a local server: `python3 -m http.server -d _site`

## Important Notes

Always test locally before pushing to remote to trigger deployment.

### What Gets Deployed

- ✅ Only files in `_site/` directory (generated by 11ty)
- ✅ Static assets (images, fonts, CSS, JS)
- ✅ Generated HTML pages
- ✅ RSS feed, sitemap, robots.txt

### What Does NOT Get Deployed

- ❌ Source files (`site/`, `.eleventy.js`, etc.)
- ❌ `node_modules/`
- ❌ `package.json`, `package-lock.json`
- ❌ `.git/` directory
- ❌ Build configuration files

### File Structure

```
.
├── site/                    # Source files (NOT deployed)
│   ├── posts/              # Markdown posts
│   ├── assets/             # Source images, fonts
│   ├── js/                  # JavaScript source
│   └── index.html           # Homepage template
├── _site/                   # Generated site (DEPLOYED)
│   ├── index.html           # Generated HTML
│   ├── bc2025/              # Generated post pages
│   └── assets/              # Copied assets
├── .eleventy.js             # 11ty config (NOT deployed)
├── package.json             # Dependencies (NOT deployed)
└── .github/
    └── workflows/
        └── deploy.yml        # Deployment automation
```

## Troubleshooting

### Deployment Fails

1. Check GitHub Actions logs (Actions tab)
2. Verify GitHub Pages is enabled with "GitHub Actions" source
3. Ensure workflow file is in `.github/workflows/deploy.yml`

## Best Practices

1. **Always test locally** before pushing:
   ```bash
   npm run build
   npm run serve
   ```

2. **Commit source code**, not generated files:
   - Add `_site/` to `.gitignore` (if not already)
   - Only commit source files in `site/`

3. **Use semantic commit messages:**
   ```bash
   git commit -m "Add new post about workshop"
   git commit -m "Fix image paths in participants page"
   ```

4. **Monitor deployments:**
   - Check Actions tab after each push
   - Verify site updates correctly

## For AI Agents

When making changes to this site:

1. **Edit source files only** (`site/` directory)
2. **Test locally** with `npm run build && npm run serve`
3. **Commit source changes** (not `_site/`)
4. **Push to `main`** - deployment is automatic
5. **Verify deployment** in GitHub Actions

The deployment workflow will:
- Build the site from source
- Deploy only the generated `_site/` directory
- Make the site live on GitHub Pages

Do not:
- ❌ Add or Commit `_site/` directory
- ❌ Manually copy files to deployment branch
- ❌ Edit files in `_site/` (they're generated)
